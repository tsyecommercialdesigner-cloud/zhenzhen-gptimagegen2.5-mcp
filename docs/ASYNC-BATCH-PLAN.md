# 异步批量提交与持久化幂等契约

本次需求：Agent 在一轮 MCP 工具调用中提交最多 10 张详情页图片的异步任务，保留检查点身份，后续查询和保存结果，不等待上游成图。沿用 `docs/API-ENDPOINT.md` 的 Images `?async=true` 与 `/images/tasks/{provider_task_id}`；不发明供应商幂等请求头。候选版本 0.3.0，实际验收见 [VALIDATION.md](VALIDATION.md)。

## 身份与工具

- `checkpointer`：Agent 指定的检查点命名空间字符串；本版为本地 SQLite 实现，不是传入 LangGraph saver 对象。
- `thread_id`：同一规划/会话的稳定字符串。
- `tasks[].task_id`：Agent 在首次提交前指定的稳定逻辑任务键。
- 三元组唯一，跨 Host/进程只在同一实际项目的检查点数据库内去重。供应商返回的编号另称 `provider_task_id`，不能与逻辑任务键混用。
- 命名空间和会话键为 1–128 字符，首位字母/数字，其余字母、数字、下划线、点、冒号或连字符；逻辑任务键仅字母、数字、下划线、连字符。

| 工具 | 契约 |
|---|---|
| `submit_image_batch` | `checkpointer, thread_id, tasks[1..10], max_concurrency=3(1..10)`；每项含稳定 task_id、generate/edit 操作及原有分组感知绘图字段。默认逆向；官转逐项显式声明。收到各上游提交响应后返回，不轮询/下载成图。 |
| `get_image_batch` | 只读本地检查点；返回线程全部记录及最后观察到的状态；未知线程返回空数组，不创建数据库、不访问供应商。 |
| `get_batch_image_task` | 按三元组查询；有 provider_task_id 时使用既有有界 GET 重试并更新状态，成功且 save=true 时保存；无编号时只返回本地状态，绝不补发 POST。 |

原有单项同步/异步工具保持兼容，未增加提交幂等保证。需要防重时，即使只有一项也使用批量入口。`get_image_task` / `wait_image_task` 仍接受供应商原始编号，可用于已知编号的人工恢复查询。

## 提交顺序与边界

1. 验证整批输入、分组、编辑参考图、mask、图片/目录；整批输入图片与 mask 合计最多 128 MiB。完成全部预检前零收费 POST，可能发生参考 URL 下载和目录可写性探测。
2. 指纹包括规范化的模型参数、操作、分组、base URL、解析后的输出目录、参考图与 mask 的 SHA-256 内容摘要。并发数、API Key 和身份键不进入指纹。重放时重新读取参考内容，源文件或 URL 内容改变会冲突；无需参考图的恢复使用本地检查点查询。
3. SQLite 事务一次保留整批记录；任一相同身份参数冲突则整批拒绝并回滚本轮新记录。事务提交成功后才可以 POST。每个线程最多 1000 条持久记录。
4. `RESERVED → SUBMITTING` 使用条件更新、提交并持久化后才允许发送一次 POST；跨 MCP 进程复用相同数据库也只能有一个调用取得提交权。数据库使用 FULL 同步，不在网络等待期间持有事务；SQLite 操作在线程池执行。
5. 每轮工具调用以 semaphore 限制在途提交数量；不同批次的并发数可以叠加，没有供应商全局限额或每账号配额。提交等待预算受各项 HTTP timeout 约束；工具不是零耗时的后台队列，不等待图片生成。
6. 有效上游编号持久化为 SUBMITTED。部分失败保留其他编号，返回 ATTENTION_REQUIRED；已知 HTTP 拒绝也保守阻止自动重发。批量接受只说明请求已被接收，不能等同图片生成成功。
7. 超时、取消、缺少编号或异常响应均进入 SUBMISSION_UNCERTAIN；进程硬中断可能停留 SUBMITTING。这两类状态不自动过期、不被重新抢占。写入失败时尽量返回已知 provider_task_id 并指引原始查询；不能通过换身份、删数据库或更换模型自动再收费。

供应商没有给出原子幂等契约，本地无法保证网络故障后的“恰好一次成功”。此实现保证保留记录时相同身份不会主动再次发送已尝试的收费请求；请求可能未发送却被保守冻结。仅 RESERVED 明确未开始请求，原参数重放可继续提交。

## 状态与恢复

| 状态 | 含义 / 下一步 |
|---|---|
| RESERVED | 已保留身份但尚未取得提交权；原参数原身份重放可继续。 |
| SUBMITTING | 已取得提交权，仍在提交或进程中断；不重发，先读取检查点和核对供应商。 |
| SUBMITTED | 有供应商编号；查询原任务。 |
| SUBMISSION_UNCERTAIN | 尝试提交但无法可靠确认；核对供应商，已知编号可原始查询，不自动重提。 |
| NOT_START / IN_PROGRESS | 排队 / 生成中；稍后再查询。 |
| SUCCESS | 云端完成；查询返回的 result.save_status/files 才能说明本地保存情况。 |
| FAILURE | 云端失败，查询返回 MCP 工具错误；保留原记录，不自动创建新任务。 |

持久数据固定在实际项目 `.runtime/checkpoints.sqlite3`，不依赖 Host CWD 或输出目录。只保存身份、指纹、base URL、输出目录、分组、状态、供应商编号、固定错误和时间；不保存提示词、原图、mask、Key 或供应商完整响应。默认无自动清理；删除或回滚数据库会丢失相应防重历史。停止所有使用该项目的 MCP 进程后备份整个 `.runtime`，升级保留它；复制到另一机器不构成跨机协调。旧版本不会使用这个新数据库，回滚后需凭已保留的 provider_task_id 查询，不能按原逻辑键重新提交。

## 验收标识

- B1：真实 MCP JSON-RPC 单次提交 10 项，POST 路由带 async=true，默认并发峰值 3，无成图 GET 或下载。
- B2：同身份同参数的顺序/同时重放与服务对象重建不产生额外 POST；改变指纹整批拒绝。
- B3：同 task_id 不同检查点/会话互不碰撞；两个独立 Python 进程只有一个取得提交权。
- B4：非法 schema、未知字段、组参数冲突、错误编辑参数、批量容量超限均在 POST 前拒绝。
- B5：超时、无编号、部分失败、取消、硬中断状态、提交后数据库写入失败均不导致自动重发。
- B6：NOT_START、暂时故障恢复、三次查询耗尽后下一轮恢复、原目录保存和 FAILURE 工具错误。
- B7：空检查点只读、数据库损坏失败关闭、参考图内容变更冲突、秘密/原图/提示词不进入数据库。
- B8：发现清单/outputSchema/手册同步；新依赖为零；全量回归、构建和独立成员安装保留既有能力。

本轮不修改真实用户 Host 配置，不提交付费任务，不自行提交、推送、合并或发布。远端 CI、真实供应商并发限额及成图能力需要另行验证。

此段边界描述最初实现轮次；后续授权和验收按日期追加，不覆盖历史结果。
