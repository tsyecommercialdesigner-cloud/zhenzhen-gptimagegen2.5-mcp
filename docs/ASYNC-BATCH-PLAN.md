# 同步/异步并发与持久化幂等契约

当前开发需求：每轮批量接受 1–20 个任务；同步执行至少支持 5 路并发，异步提交默认并发 5、最多 20，未获得结果的原子异步任务自动每 90 秒查询一次，保留跨重启幂等、哈希和恢复语义。沿用 `docs/API-ENDPOINT.md` 的 Images `?async=true` 与 `/images/tasks/{provider_task_id}`；不发明供应商幂等请求头。历史版本为 0.3.0/0.3.1；本次功能尚未发布，历史验收见 [VALIDATION.md](VALIDATION.md)。

## 身份与工具

- `checkpointer`：Agent 指定的检查点命名空间字符串；本版为本地 SQLite 实现，不是传入 LangGraph saver 对象。
- `thread_id`：同一规划/会话的稳定字符串。
- `tasks[].task_id`：Agent 在首次提交前指定的稳定逻辑任务键。
- 三元组唯一，跨 Host/进程只在同一实际项目的检查点数据库内去重。供应商返回的编号另称 `provider_task_id`，不能与逻辑任务键混用。
- 命名空间和会话键为 1–128 字符，首位字母/数字，其余字母、数字、下划线、点、冒号或连字符；逻辑任务键仅字母、数字、下划线、连字符。

| 工具 | 契约 |
|---|---|
| `submit_image_batch` | `checkpointer, thread_id, tasks[1..20], max_concurrency=5(1..20)`；每项含稳定 task_id、generate/edit 操作及原有分组感知绘图字段。默认逆向；官转逐项显式声明。收到各上游提交响应后返回，工具自身不等待成图；后台每90秒查询并保存。 |
| `run_image_batch` | `checkpointer, thread_id, tasks[1..20], max_concurrency=5(1..5)`；同步生成/编辑，持久化结果清单并校验哈希后返回；复用相同三元组不收费重发。 |
| `get_image_batch` | 只读本地检查点；返回线程全部记录及最后观察到的状态；未知线程返回空数组，不创建数据库、不访问供应商。 |
| `get_batch_image_task` | 按三元组查询；有 provider_task_id 时使用既有有界 GET 重试并更新状态，成功且 save=true 时保存；无编号时只返回本地状态，绝不补发 POST。 |

单项同步/异步工具兼容原调用，新增可选稳定 `idempotency_key`，四个入口共用 `(single, default, idempotency_key)`；相同键不同请求或同步/异步模式冲突。未传键时仍无防重保证。`get_image_task` / `wait_image_task` 仍接受供应商原始编号，可用于已知编号的人工恢复查询。

## 提交顺序与边界

1. 验证整批输入、分组、编辑参考图、mask、图片/目录；整批输入图片与 mask 合计最多 128 MiB。完成全部预检前零收费 POST，可能发生参考 URL 下载和目录可写性探测。
2. 指纹包括规范化的模型参数、操作、分组、base URL、解析后的输出目录、参考图与 mask 的 SHA-256 内容摘要。并发数、API Key 和身份键不进入指纹。重放时重新读取参考内容，源文件或 URL 内容改变会冲突；无需参考图的恢复使用本地检查点查询。同步重放读取结果清单并重新验证输出文件字节数和 SHA-256，缺失或篡改报错而不重发收费请求。
3. SQLite 事务一次保留整批记录；任一相同身份参数冲突则整批拒绝并回滚本轮新记录。事务提交成功后才可以 POST。每个线程最多 1000 条持久记录。
4. `RESERVED → SUBMITTING` 使用条件更新、提交并持久化后才允许发送一次 POST；跨 MCP 进程复用相同数据库也只能有一个调用取得提交权。数据库使用 WAL + FULL 同步，不在网络等待期间持有事务；SQLite 操作在线程池执行。
5. 每轮以 semaphore 限制并发，单个 MCP 进程跨工具共享同步5/异步提交20的并发槽；多进程或供应商账号之间未设置全局配额。提交等待预算受各项 HTTP timeout 约束；异步工具不是零耗时队列，不等待成图；同步工具等待成图并保存结果。
6. 有效上游编号持久化为 SUBMITTED。部分失败保留其他编号，返回 ATTENTION_REQUIRED；已知 HTTP 拒绝也保守阻止自动重发。批量接受只说明请求已被接收，不能等同图片生成成功。
7. 超时、取消、缺少编号或异常响应均进入 SUBMISSION_UNCERTAIN；进程硬中断可能停留 SUBMITTING。这两类状态不自动过期、不被重新抢占。写入失败时尽量返回已知 provider_task_id 并指引原始查询；不能通过换身份、删数据库或更换模型自动再收费。

供应商没有给出原子幂等契约，本地无法保证网络故障后的“恰好一次成功”。此实现保证保留记录时相同身份不会主动再次发送已尝试的收费请求；请求可能未发送却被保守冻结。仅 RESERVED 明确未开始请求，原参数重放可继续提交。

## 状态与恢复

| 状态 | 含义 / 下一步 |
|---|---|
| RESERVED | 已保留身份但尚未取得提交权；原参数原身份重放可继续。 |
| SUBMITTING | 已取得提交权，仍在提交或进程中断；不重发，先读取检查点和核对供应商。 |
| SUBMITTED | 有供应商编号；查询原任务。 |
| SUBMISSION_UNCERTAIN | 尝试提交但无法可靠确认；核对供应商，已知编号可原始查询，不自动重提。 |
| NOT_START / IN_PROGRESS | 排队 / 生成中；稍后再查询。 |
| SUCCESS | 云端完成；查询返回的 result.save_status/files 才能说明本地保存情况。 |
| FAILURE | 云端失败，查询返回 MCP 工具错误；保留原记录，不自动创建新任务。 |

持久数据固定在实际项目 `.runtime/checkpoints.sqlite3`，不依赖 Host CWD 或输出目录。只保存身份、指纹、base URL、输出目录、分组、状态、供应商编号、固定错误、时间、轮询租约及本地结果清单；不保存提示词、原图、mask、Key 或供应商完整响应。默认无自动清理；删除或回滚数据库会丢失相应防重历史。停止所有使用该项目的 MCP 进程后备份整个 `.runtime`，升级保留它；复制到另一机器不构成跨机协调。旧版本不会使用这个新数据库，回滚后需凭已保留的 provider_task_id 查询，不能按原逻辑键重新提交。

## 验收标识

- B1：真实 MCP JSON-RPC 单次提交20项，POST路由带async=true，默认并发峰值5、可显式20；返回提交确认时不等待成图。
- B2：同身份同参数的顺序/同时重放与服务对象重建不产生额外 POST；改变指纹整批拒绝。
- B3：同 task_id 不同检查点/会话互不碰撞；两个独立 Python 进程只有一个取得提交权。
- B4：非法 schema、未知字段、组参数冲突、错误编辑参数、批量容量超限均在 POST 前拒绝。
- B5：超时、无编号、部分失败、取消、硬中断状态、提交后数据库写入失败均不导致自动重发。
- B6：NOT_START、暂时故障恢复、三次查询耗尽后下一轮恢复、原目录保存和 FAILURE 工具错误。
- B7：空检查点只读、数据库损坏失败关闭、参考图内容变更冲突、秘密/原图/提示词不进入数据库。
- B8：发现清单/outputSchema/手册同步；新依赖为零；全量回归、构建和独立成员安装保留既有能力。

本轮不修改真实用户 Host 配置，不提交付费任务，不自行提交、推送、合并或发布。远端 CI、真实供应商并发限额及成图能力需要另行验证。

此段边界描述最初实现轮次；后续授权和验收按日期追加，不覆盖历史结果。

## 自动查询与数据库决策（本次开发）

- 服务 lifespan 启动/关闭后台轮询；确认的单项与批量任务按 `(base_url, provider_task_id)` 登记，首次90秒后查询，完成本轮后至少再等90秒，扫描间隔5秒。每轮最多5个并行 GET，自动重试只能等下一轮，不触发短间隔 GET 重试。
- 排队/运行中/查询失败/结果部分保存失败继续；云端 FAILURE 或 SUCCESS 且 save_status=saved 停止。只有成功保存的本地路径、大小、哈希等清单持久化，不存上游完整响应、提示词、图像或URL/Key。同步响应中的临时下载支持最多3次只读重试，总预算120秒；坏图与哈希冲突不重试。
- schema1→2 事务迁移保留既有任务及防重键，登记有 provider_task_id 的旧批量；未登记的旧单项 JSON 元数据不自动导入。服务意外退出后租约到期恢复，租期为配置HTTP预算+180秒保存预算+90秒余量；旧工作者不能覆盖新令牌。
- 使用本地 SQLite WAL、FULL、5秒锁等待、短事务和到期索引；网络/图片写入不持有SQLite事务。20项属于低写入频率工作流，先验证并发竞争和重启恢复，不增加数据库服务或依赖。跨机器共享存储、账号级配额和更大规模另行设计；需要时可评估免费的开源 PostgreSQL。
- 升级先停服务并备份整个 `.runtime`，保留 WAL/SHM。schema2 不兼容旧程序直接读取，回滚保留新库并凭供应商编号恢复，不能删除数据库或换键重复收费。单独的图像哈希仅验证传输/本地内容一致性，不冒充供应商签名。

新增验收：C1 同步20项峰值5且并行批次共享槽；C2 异步20项并发20；C3 单项键重复/冲突及同步/异步模式隔离；C4 输出篡改与同步未知结果不重提；C5 90秒自动调度、重启恢复、部分保存恢复与终态停止；C6 多进程事务租约与schema1迁移；C7 真实lifespan启动和关闭；C8 新工具清单、文档、全量回归、构建和独立安装一致；C9 同步失败清单在重放后仍可诊断，异步下载失败后恢复保存并清除旧错误，全程不新增 POST。测试使用受控供应商传输，不产生费用。

持久清单可包含保存失败的脱敏诊断：`download_errors` 仅保留图片索引和脱敏错误，URL 字段为 null；不存完整响应、URL、提示词或图片。历史五项真实请求的保存失败根因仍未确认，不能由受控恢复测试宣称已解决。
